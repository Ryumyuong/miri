# 예약 취소 데이터 적용 안내

2026-10-16 로컬 수정용. 운영 DB에는 어떤 작업도 실행하지 않았다.

현재 저장소는 SQL이 아닌 Firestore다. 예약과 승객에 선택 필드(status, cancelledAt, cancellationHistory)를 추가했다. 필드가 없는 기존 문서는 활성으로 읽으므로 필수 백필·DDL·신규 인덱스가 없다. 스키마 계약은 `20261016-reservation-cancellation.json` 참조.

최소 적용 절차 (추후 배포 승인 후):

1. 기존 예약 컬렉션의 접근 제한된 백업을 확보한다. 공개 저장소나 보고서에 고객 데이터를 복제하지 않는다.
2. 별도 비운영 Firebase 프로젝트/에뮬레이터에서 팀 취소·복구, 승객 취소·복구, 동시 편집 충돌을 확인한다.
3. 기존 관리자 탭을 닫고 새 클라이언트를 함께 적용한다. 구버전은 hard delete를 사용하고 취소 승객을 집계하므로 혼용하지 않는다.
4. 기존 문서는 그대로 둔다. 신규 취소 시 문서 또는 passengers 배열 내 해당 승객에 상태와 이력이 기록된다. 복구는 상태만 활성으로 바꾸고 취소일시·이력을 유지한다.
5. 취소 전후 집계와 복구 후 정원 초과 여부를 확인한다. 복구는 기존 예약 정보를 복원하므로 정원 초과를 자동 차단하지 않는다.

롤백 시 기존 구버전을 그대로 재배포하면 취소 기록이 다시 활성 집계될 수 있다. 취소 필드를 이해하는 버전을 유지하거나 별도 롤백 패치를 먼저 준비한다. 취소 필드/이력을 지우는 역마이그레이션은 제공하지 않는다.

과거 영구 삭제는 신뢰할 백업 없이는 복구할 수 없다. 삭제 시각을 추정하거나 과거 기록을 생성하지 않는다. 새 기능에는 영구 삭제 버튼이 없다.

현재 저장소의 `firestore.rules`는 기존부터 `allow read, write: if true`이며 관리자 인증은 데모 방식이라고 명시돼 있다. 이번 작업은 규칙이나 권한을 변경하지 않았다. 운영 환경에서 이 규칙이 적용됐는지는 확인하지 않았으며, 운영 적용 전에 실제 규칙과 관리자 인증을 별도로 검증해야 한다. 취소 시각은 현재 앱 방식에 맞춘 클라이언트 ISO 시각이고 인증된 담당자 식별자는 없다. 보안 감사용 불변 이력/서버 시각을 보장하는 설계는 아니다.
